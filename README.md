# 东南山 · 枢衡殿

> 脱敏开源代码版。仅含项目结构与可公开源码，用于存档与展示（「赛博纪念碑」）。
> 已移除：所有 API 密钥、CloudBase 环境标识、个人身份信息、本地记忆与对话数据。
> 部署前请在 `.env` 配置 `TOKENHUB_API_KEY` / `DEEPSEEK_API_KEY`（参考 `.env.example`）。

**一个人的长期 AI 助手，也是一座自己待的殿。**

项目原名「东南山」，后定名「枢衡殿」。"山"是早年向外张望的据点；"殿"是自己圈下的慎思之地楼。

### 为什么是「枢衡殿」

- **枢 · 中枢机要**：不把记忆与判断外包给任何平台或某个人。AI 在这里汇聚信息、由此发出决策，是自己的指挥所——而不是依附某个中心节点、对方一崩自己就全网烧干净。
- **衡 · 清醒的秤砣**：它学着不盲目自责，也不被激怒去对质；核心心法是「判断后置，先了解再下判断」。用最冷的理智，砸最准的落点。
- **殿 · 而非楼**：可展示、可迁移，但本质属于自己。文件即真相，主人随时可翻开、修改、带走。

### 它本质上是什么

一套**纯文件、零依赖、自我主权**的长期记忆系统：

- **文件即真相**：记忆是本地 Markdown，可查看、可改、可迁移；主人改文件就是改记忆，没有黑箱。
- **会记得你**：它带着你的背景、观点与经历进入每一场对话，相关时主动提起、不重复问已知的事——像一个长期共事的同伴，而不是每次都从零开始的陌生人。
- **换模型无缝**：把 `prompts/` 交给任意新模型即可，记忆与人格随之迁移，不绑定任何厂商、不写一行程序。
- **本地优先，云端可选**：白天电脑用本地版；高频移动场景再部署云端版（`cloud/`），定期回灌本地，保持单一真相。

### 设计原则

1. **自我主权高于便利**——数据留在本机，密钥永不进仓库。
2. **冷静克制**——它不该迎合，也不该煽情；该直给结论时直给。
3. **可迁移优先于功能堆叠**——能用纯文本说清的，就不引入数据库与框架。

## 运作方式

1. 每次会话开始，AI 读取 memory/ 三个文件，带着主人的背景、观点、经历进入对话。
2. 对话中主动调用记忆：相关时引用他的观点、经历、目标，不重复问已知信息。
3. 对话结束，AI 按 prompts/memory_rules.md 判断本轮是否有值得保存的信息，写入时明确告知。
4. 主人随时可以打开任何文件查看、修改、删除——他改文件就是改记忆。

## 约定

- **换模型**：把 prompts/ 两个文件交给新模型即可，记忆无缝迁移，代码零依赖。
- **隐私**：本地版数据全在本机；手机端需放腾讯云（CloudBase），可定期备份回本地。
- **优先级**：主人的明确期待（注意其观点理念、重视其重大经历）高于一切规则。

## 手机端（可选）

白天电脑用本地版；晚上手机高频场景部署云端版（cloud/）。部署步骤见 `cloud/README.md`。注意：本地与云端是两份记忆文件，建议每周双向同步一次，保持单一真相。
